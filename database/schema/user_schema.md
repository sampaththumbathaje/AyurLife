# User Schema – AyurLife

## Collection Name
`users`

## Description
The `users` collection stores all registered user information for the AyurLife system.  
It supports authentication, personalization, chatbot interaction history, Prakriti storage, and the Dinacharya planner.

This schema is designed using a **document-based approach**, leveraging MongoDB’s support for nested objects to efficiently store related user data in a single document.

---

## Fields Overview

### 1. `_id`
- **Type:** ObjectId
- **Description:** Unique identifier automatically generated by MongoDB for each user.

---

### 2. `name`
- **Type:** String
- **Description:** Full name of the registered user.

---

### 3. `email`
- **Type:** String (Unique)
- **Description:** User’s email address used for login and communication.
- **Constraint:** Must be unique across the collection.

---

### 4. `password_hash`
- **Type:** String
- **Description:** Encrypted password using a secure hashing algorithm (bcrypt).
- **Note:** Plain-text passwords are never stored.

---

### 5. `role`
- **Type:** String
- **Allowed Values:** `user`, `admin`
- **Description:** Defines access level of the user.

---

## Prakriti Information

### 6. `prakriti`
- **Type:** Object
- **Description:** Stores the user’s Ayurvedic body constitution determined using ML.

#### Subfields:
| Field | Type | Description |
|------|------|------------|
| `type` | String | Predicted Prakriti (Vata / Pitta / Kapha) |
| `last_updated` | ISODate | Timestamp of last prediction |
| `confidence` | Float | Confidence score of the ML model |

---

## Saved Remedies

### 7. `saved_remedies`
- **Type:** Array of Objects
- **Description:** Stores remedies bookmarked by the user.

#### Subfields:
| Field | Type | Description |
|------|------|------------|
| `remedy_id` | String | Reference to remedy |
| `name` | String | Remedy name |
| `saved_at` | ISODate | Time when saved |

---

## Dinacharya Planner

### 8. `dinacharya_planner`
- **Type:** Array of Objects
- **Description:** Tracks daily Ayurvedic routine tasks for the user.

#### Subfields:
| Field | Type | Description |
|------|------|------------|
| `task_id` | String | Reference to Dinacharya task |
| `task_name` | String | Name of the task |
| `time` | String | Scheduled time |
| `completed` | Boolean | Completion status |
| `date` | Date | Task date |

---

## Chat History Reference

### 9. `chat_history`
- **Type:** Array of Objects
- **Description:** Stores brief chat interaction summaries for dashboard display.

#### Subfields:
| Field | Type | Description |
|------|------|------------|
| `message_id` | String | Chat message identifier |
| `sender` | String | `user` or `bot` |
| `message` | String | Chat message content |
| `timestamp` | ISODate | Message timestamp |

> **Note:** Detailed conversations are stored separately in the `chat_history` collection.

---

## Metadata

### 10. `created_at`
- **Type:** ISODate
- **Description:** Account creation timestamp.

### 11. `updated_at`
- **Type:** ISODate
- **Description:** Last profile update timestamp.

---

## Design Considerations

- Uses **nested documents** to reduce joins and improve read performance.
- Sensitive data is secured via hashing and role-based access.
- Supports **ML integration**, chatbot personalization, and dashboard features.
- Designed for scalability and future enhancements (e.g., health history).
